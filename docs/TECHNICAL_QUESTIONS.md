# Technical Questions

## Significant architectural question identified by each team member

| Member & Pack | Single Focused Architectural Question | Evaluated Trade-Offs & Chosen Resolution |
|---|---|---|
| Pol<br>Pack 1: Core Engine & Async (AQ-01) | How can asynchronous workflow execution guarantee zero event loss and avoid duplicate side effects across worker crashes and retries, given that delivery is at-least-once and not every provider supports idempotency keys? | Compared synchronous execution, SQL polling queues, and Redis Streams. Selected Transactional Outbox (PostgreSQL PENDING sweep) + Redis Streams (Consumer Groups + XAUTOCLAIM), atomic SQL worker claims, advisory-locked single-leader polling, and per-REAction idempotency keys with step-aware DLQ replay, documenting the residual duplicate window for non-idempotent providers. |
| Edu<br>Pack 2: Connectors & API Contract (AQ-02) | How can third-party Actions and REActions declare their schemas so new integrations plug into the engine without core edits while enforcing save-time validation and API contract parity? | Compared static JSON catalogs vs. a Go startup plugin registry. Selected typed TriggerNode/ReactionNode interfaces exposing InputSchema() and OutputSchema() to dynamically build /about.json, enforce save-time {{ node.key }} validation (HTTP 422), and verify live endpoints against openapi.yaml in CI. |
| Achille<br>Pack 3: Security, Auth & DevOps (AQ-03) | How can delegated OAuth2 credentials and user sessions remain protected at rest while surviving short-lived token expirations during autonomous background execution? | Evaluated plaintext/base64 DB storage vs. authenticated encryption, and manual re-linking vs. background refresh. Selected Argon2id/JWT + verified-email Google OIDC linking, proactive OAuth2 refresh before expiry, AES-GCM 256 encryption at rest with env-injected master keys, and CI secret/CVE gates. |
| Keigan<br>Pack 4: Web & Android Clients (AQ-04) | How can React Web and React Native Android render dynamic service forms and execution histories from /about.json without hardcoding business rules while maintaining cross-client parity and WCAG AA compliance? | Compared per-service hardcoded screens vs. schema-driven form generation, and native Kotlin vs. React Native. Selected React (Web) + React Native (Android) sharing TypeScript OpenAPI types, schema-driven builders/viewers, runtime server URL configuration on Android, day-one EN/ES i18n, and axe/Accessibility Scanner WCAG AA verification. |
