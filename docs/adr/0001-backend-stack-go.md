# ADR 0001: Backend stack (Go)

**Status:** Accepted
**Date:** 2026-11-15 (evidence added 2026-11-24)

## Why a record

It fixes the language of the whole server and what the team had to learn. Changing it after the MVP means rewriting the server.

## Context

The server runs hooks that poll many external services in parallel, exposes an OpenAPI-described HTTP API to the web and mobile clients, and ships in Docker. Four options were compared in the spikes and in [`docs/tech-selection/backend-selection.md`](../tech-selection/backend-selection.md): Go, NestJS, Hono/Bun and FastAPI. The matrix totals are within two points (71, 72, 73, 72), so they do not decide.

## Decision

Go with the standard library (`net/http`, `database/sql`).

## Alternatives considered

- **NestJS:** best ecosystem and code-first OpenAPI (scored 5), but a 401 MB image, an in-process scheduler that needed a manual guard, and a large dependency tree.
- **Hono / Bun:** easiest to learn (5), but the smallest ecosystem for our needs.
- **FastAPI:** OpenAPI for free (5), but no scheduler and a 214 MB image. Kept as the fallback.

## Consequences

- **Positive:** goroutines fit parallel hooks; 21 MB static image; few dependencies; strong typing.
- **Negative:** nobody in the team knew Go (learning curve scored 2); OpenAPI generation from Go code and OAuth2 / OIDC were not tested in the spikes; more code to write than with a framework.
- **Mitigation:** test OpenAPI and OAuth2 first. If either fails, switch to FastAPI.

## Evidence

- One binary with three roles chosen by `ROLE` ([`server/cmd/area/main.go`](../../server/cmd/area/main.go)). HTTP routing uses only `net/http` and its method patterns (`GET /about.json`).
- The image is 16 MB (distroless static, [`server/Dockerfile`](../../server/Dockerfile), measured on 2026-11-24).
- **OpenAPI risk:** solved spec-first instead of generating the description from Go. [`server/api/openapi.yaml`](../../server/api/openapi.yaml) is written by hand, linted with Redocly in CI, served at `/docs`, and the web client is generated from it ([`web/orval.config.ts`](../../web/orval.config.ts)). The cost is that the spec can drift from the handlers; F-12 will check live responses against it.
- **Changed during the MVP:** PostgreSQL is used through `pgx` directly, with queries generated by `sqlc` ([`server/sqlc.yaml`](../../server/sqlc.yaml)), not through `database/sql`. Other libraries added: `golang-migrate`, `go-redis`, `golang-jwt` and `x/crypto` (Argon2id).
- **Not validated yet:** OAuth2 / OIDC (M-14 is in progress). It is the main open risk of this decision.

## Under the main alternative (FastAPI)

- The OpenAPI description and `/docs` would come from the Pydantic models, so there would be no hand-written spec to keep in sync.
- The scheduler and the workers would need a separate library and process, since FastAPI has none; polling would run on `asyncio` instead of goroutines.
- The server image would be around 214 MB instead of 16 MB.
